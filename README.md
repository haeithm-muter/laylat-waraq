# 🃏 ليلة ورق

لعبة أسئلة وتحديات جماعية بالعربي، للتجمعات الشبابية. React Native (Expo) + TypeScript، لاندسكيب بالكامل.

انظر الـ PRD الكامل لتفاصيل المنتج والخطة الزمنية (5 أيام).

## ⚠️ مهم: من اليوم 2 صار لازم Dev Client (مو Expo Go)

شاشات السيرفر المحلي (`سيرفر لعب`، `الانضمام لسيرفر`) تحتاج مكتبات شبكة حقيقية
(`react-native-tcp-socket`, `react-native-udp`) للتواصل بين الأجهزة على نفس
الواي فاي، بالإضافة للكاميرا (`expo-camera`) لمسح QR. هذي مكتبات native ما
تجيها Expo Go الجاهز من المتجر — أي تطبيق يحتاج مكتبات native خارج مجموعة
Expo الأساسية لازم "Dev Client" مبني خصيصًا للمشروع.

**شاشات اليوم 1 (تسجيل الدخول، الرئيسية) وشاشات التنقل البسيطة باليوم 2
(اختيار الوضع، مع الأصدقاء) غالبًا تشتغل بـ Expo Go عادي** — بس ما تأكدت
منها بجهاز حقيقي، وشاشتي إنشاء/الانضمام للسيرفر أكيد محتاجتين Dev Client
عشان أي محاولة فعلية تشغّل الشبكة.

ابني الـ Dev Client مرة وحدة (يبقى صالح طول التطوير، ترجعله بـ `npx expo
start` عادي بعدها بدون إعادة بناء إلا إذا أضفت مكتبة native جديدة):

```bash
# الخيار الأسهل — بناء سحابي، ما يحتاج Android Studio عندك (يحتاج حساب Expo مجاني)
npx eas login
npx eas build --profile development --platform android
# بعد ما يخلص، نزّل الـ APK وثبّته على جوالك

# أو محليًا إذا عندك Android Studio + SDK مثبتين
npx expo prebuild
npx expo run:android
```

بعدها شغّل السيرفر عادي وافتحه من نفس الـ Dev Client (مو Expo Go):

```bash
npx expo start --dev-client
```

## المتطلبات

- Node.js 20+ (تم البناء والاختبار على Node 24)
- **للتطوير على اليوم 1 فقط:** تطبيق Expo Go كافي
- **من اليوم 2:** Dev Client (شوف فوق) — إما بناء EAS سحابي أو Android Studio / Xcode محليًا
- جهازين على الأقل على نفس شبكة الواي فاي لاختبار السيرفر المحلي فعليًا (مضيف + لاعب واحد على الأقل)

## الإعداد

```bash
npm install
cp .env.example .env
```

افتح `.env` وعبّي مفاتيح Firebase الحقيقية (Firebase Console → Project settings → SDK setup)، ومفتاح Facebook App ID إذا بغيت تفعّل الدخول عبر فيسبوك. بدون هذي المفاتيح، التطبيق يشتغل بالكامل ويعرض كل الشاشات، لكن أي محاولة تسجيل دخول فعلية بترجع رسالة "لم يتم إعداد تسجيل الدخول بعد" بدل ما تتعطل.

**Firebase Auth:** فعّل من الـ Console (Authentication → Sign-in method): Email/Password، Apple، Facebook.

**Apple Sign In:** يشتغل بس على iOS builds حقيقية (مو Expo Go، ومو Android) — يعتمد على `bundleIdentifier` بملف `app.json`، ما يحتاج مفتاح إضافي بـ `.env`.

**Facebook Login:** لازم تضيف `laylatwaraq://` كـ redirect URI صحيح بإعدادات Facebook Login للتطبيق.

```bash
                                 # عربية واضحة بدل ما تكسر الشاشة)
```

## قرارات تقنية مهمة

- **Expo SDK 57** بدل SDK 51 المذكور بالـ PRD — SDK 51 قديم (2024) وما يدعمه Expo Go الحالي ولا يعمل بشكل موثوق مع Node 24. باقي الـ stack (Firebase, Zustand, Expo Router...) زي ما هو بالـ PRD تمامًا.
- **الاتجاه (Landscape):** مقفول عبر `expo-screen-orientation` وقت التشغيل (يشتغل حتى بـ Expo Go)، بالإضافة لإعداد `app.json` اللي يقفله على مستوى Android/iOS native وقت البناء.
- **RTL:** كل شاشة مبنية RTL بالكامل (محاذاة نص، `row-reverse`، إلخ) يدويًا لكل عنصر. تعمّدت عدم استدعاء `I18nManager.forceRTL()` + إعادة تشغيل إجباري بهالمرحلة المبكرة من البناء تجنبًا لمخاطر حلقة إعادة تشغيل أثناء التطوير السريع؛ فحص RTL الشامل مجدول أصلاً باليوم 5 بالـ PRD.
- **الخلفية الكرتونية بشاشة الدخول:** رسمة SVG أصلية (طاولة ورق + أضواء + أوراق متطايرة) مو تصميم مُكلّف من فنان — بديل مؤقت لائق يقدر يتغيّر لاحقًا بسهولة (`components/ui/CardTableBackground.tsx`) بدون ما يمس باقي الشاشة.
- **أيقونة التطبيق والـ splash:** لسه placeholder من Expo، يحتاج تصميم نهائي قبل الإصدار (مجدول ضمن يوم 5).
- **"WebSocket محلي" بالـ PRD → TCP + UDP فعليًا:** الأجهزة داخل React Native ما تقدر تفتح WebSocket server حقيقي (ولا حتى Node.js — الجملة بالـ PRD "Node.js via Expo" غير دقيقة تقنيًا). استخدمت `react-native-tcp-socket` لقناة اللعبة (رسائل JSON مفصولة بسطر جديد) و`react-native-udp` لبث اكتشاف السيرفر بالكود على الشبكة المحلية. نفس الهدف (تواصل فوري بدون إنترنت، المضيف هو المرجع) بأسلوب أبسط وأوثق من تطبيق بروتوكول WebSocket يدويًا.
- **مسح QR بدون اكتشاف:** رمز الـ QR يشفّر IP والمنفذ والكود مباشرة، فالانضمام عن طريقه ما يعتمد على اكتشاف UDP إطلاقًا — لو صار فيه مشكلة بالبث المحلي (بعض الراوترات تمنعه)، مسح QR يبقى طريق انضمام موثوق دائمًا.
- **مكتبات الشبكة (`react-native-tcp-socket`, `react-native-udp`):** أفضل الخيارات المتوفرة بالمنظومة حاليًا (تأكدت من عدم وجود بديل أنشط بحثًا بـ npm)، لكن `expo-doctor` ينبّه إن `react-native-udp` قليل الصيانة و`react-native-tcp-socket` غير مختبر رسميًا على New Architecture (المعمارية الوحيدة بـ SDK 57، ما فيه رجوع للقديمة). ما قدرت أختبرهم على جهاز حقيقي بهالبيئة (ما فيه Android SDK/emulator متاح لي) — الاختبار الفعلي بجهازين حقيقيين ضروري قبل ما تعتمد عليها كليًا.

## حالة اليوم 3 ✅

- **شاشة اختيار الفئة للدور**: شبكة الفئات مع عدد الأسئلة المتبقية لكل فئة، والفئة تُعطّل وتُظلّل تلقائيًا لما تخلص أسئلتها
- **تخطيط اللعب (سيرفر)**: ثلاث بطاقات — المؤقت يسار، السؤال بالنص (الأعرض)، بطاقة القانون يمين، مطابق للـ PRD §4.9
- **تخطيط "مع الأصدقاء"**: السؤال يأخذ المساحة الأكبر، وعمود جانبي يجمع المؤقت وبطاقة القانون (§4.12)
- **المؤقت**: عدّاد رقمي، يصير أحمر تحت 10 ثواني، زر إيقاف مؤقت/متابعة، وعند الصفر يكشف الإجابة تلقائيًا
- **الرهان**: راهن (×2) / لا تراهن — يُقرَّر والسؤال لسه مخفي، وتتضاعف النقاط أو تنخصم الحصة
- **كشف الإجابة + "من جاوب؟"**: نافذة تعرض الإجابة وأزرار اللاعبين + "لا أحد"
- **لوحة النقاط**: كل اللاعبين مع نقاطهم وأزرار +/- يدوية، واللاعب صاحب الدور مميّز
- **تراجع**: يرجّع آخر عملية تنقيط بالكامل (النقاط، الدور، السؤال، رصيد الفئة)
- **نهاية اللعبة**: ترتيب نهائي، ورسالة "انتهت الأسئلة" مع خيار إعادة الأسئلة لما تخلص كلها

**بنك الأسئلة:** 78 سؤال حقيقي (6 لكل فئة × 13 فئة) عشان الحلقة تكون قابلة للعب والاختبار فعليًا من الآن. الـ6000 سؤال الكاملة والقوانين الـ30 مجدولة لليوم الرابع حسب الـ PRD، والمحمّل (`content/index.ts`) مبني عشان يتوسّع لها بدون تغيير في حلقة اللعب.

**قرارات أثناء التنفيذ:**
- **النقاط تُشتق من الصعوبة** (سهل 200 / متوسط 300 / صعب 400) حسب §13، فما تنكتب يدويًا مع كل سؤال — يقلل الخطأ ويسهّل توليد المحتوى باليوم الرابع.
- **الرهان "ضعف أو لا شيء"**: إجابة صحيحة = ×2، ما حد جاوب = تنخصم الحصة من صاحب الدور. خصم الـ200 عند الإجابة الخاطئة تبع القانون رقم 2 (§6) وبينضاف مع محرّك القوانين باليوم الرابع، مو جزء من الحساب الأساسي.
- **المؤقت مبني على وقت النهاية (deadline) مو عدّاد تنازلي**: لو تعلّق خيط الجافاسكربت (تنقّل، رسم ثقيل) يبقى العدّ دقيق بدل ما يمشي زيادة.
- **الأصوات مؤجلة لليوم الخامس** حسب الـ PRD (تحتاج ملفات صوت)، وتعمّدت ما أضيف مكتبة native جديدة عشانها الآن عشان ما أجبرك تعيد بناء الـ Dev Client مرة ثانية.

تم التحقق: `tsc --noEmit` نظيف، `expo-doctor` (21/21)، بناء Metro كامل لـ Android (1759 موديول)، **ولعبت الحلقة كاملة فعليًا بالمتصفح**: اخترت فئة ← راهنت ×2 ← عدّ المؤقت 0:40←0:00 ← كشف تلقائي ← منح النقاط (600 بالرهان) ← دوران الدور ← تراجع (رجّع النقاط والدور والسؤال) ← مسار "لا أحد" (خصم 300) ← تعديل يدوي (+100) ← نفاد فئة (تعطّلت وظُلّلت) ← نفاد كل الأسئلة (نهاية + إعادة أسئلة). لقيت وأصلحت خللين أثناء البناء: مُحدِّد (selector) كان يبني كائن جديد كل مرة وكان بيسبب إعادة رسم لا نهائية مع zustand v5، وزر إيقاف المؤقت كان يظهر بمراحل ما يشتغل فيها.

**ملاحظة على الشفافية:** أثناء الاختبار ظننت إن المؤقت فيه خلل (كان يقفز من 20 لـ9)، وأعدت كتابة `useTimer`. تبيّن بعد قياس دقيق داخل الصفحة إن **ما كان فيه خلل أصلاً** — كنت أقيس تأخير أدوات الاختبار نفسها (كل استدعاء للمتصفح ياخذ ~10 ثواني والمؤقت يمشي خلالها). إعادة الكتابة بحد ذاتها تبسيط سليم ومُتحقق منه (يعدّ، ويتوقف مؤقتًا، ويكمل)، لكنها ما كانت تصلح عيبًا حقيقيًا.

### ⚠️ فجوة المحتوى — كن على علم فيها

بنك الأسئلة فيه حاليًا **78 سؤال** (6 لكل فئة)، والـ PRD يستهدف **6000+**. ما عبّيت الفرق بأسئلة مولّدة على السريع عن قصد: كتابة آلاف الأسئلة العربية الدقيقة — خصوصًا بالدين والتاريخ — تحتاج مراجعة بشرية، وتوليدها بدون تحقق يعني نشر أخطاء معرفية داخل اللعبة.

البنية جاهزة تمامًا للتوسّع (`content/seed/<category>.json`، والنقاط تُشتق من الصعوبة تلقائيًا). وأضفت **فاحص سلامة** يمسك الأخطاء الشائعة عند الإضافة بالجملة:

```bash
npm run validate:content
```

يفحص: تكرار المعرّفات، الحقول الفاضية، صعوبة غير صحيحة، وعدم تطابق الفئة مع اسم الملف (خطأ يخلّي السؤال ما ينسحب أبدًا). خطة الوصول لـ6000 حسب §13 بالـ PRD: توليد على دفعات حسب أولوية الفئات، مراجعة الدين والتاريخ يدويًا، وتشغيل الفاحص قبل كل دمج.

- **الأصوات**: 5 مؤثرات (صح، خطأ، تكّة المؤقت، إنذار انتهاء الوقت، فوز) عبر `expo-audio` — الملفات **مُولَّدة برمجيًا** (`scripts/generate-sounds.mjs`, نغمات جيبية خام مكتوبة كـ WAV مباشرة، بدون تحميل أي ملف خارجي) بدل التوليد اليدوي، بانتظار تصميم صوتي نهائي لاحقًا. مربوطة بمفتاح "الصوت" الموجود أصلاً بلوحة الإعدادات (كان جاهزًا بالواجهة من قبل بدون أي صوت يُشغَّل فعليًا). نقاط الربط: تكّة كل ثانية بآخر 10 ثواني، إنذار عند انتهاء الوقت، صح/خطأ عند منح النقاط، وفوز عند فتح شاشة النتائج.
- **الأنيميشن** (بنفس `Animated` API الموجودة، بدون مكتبة native جديدة): تلاشي عند كشف السؤال، نبضة خفيفة على المؤقت بآخر 10 ثواني، نافذة كشف الإجابة وقوانين والتحدي البدني كلها صارت تدخل/تخرج بتلاشي+تكبير بدل الظهور الفوري (hook مشترك `useMountTransition`)، ونبضة على رقم النقاط عند تغيّره.
- **فحص RTL**: صلّحت خلل حقيقي بشبكة اختيار المواضيع (كانت ناقصة `row-reverse` فتظهر بترتيب معكوس) — تحققت من الإصلاح بقياس إحداثيات البطاقات فعليًا بالمتصفح، مو بس بصريًا. صلّحت أيضًا شارة الاختيار (كانت بالزاوية الخطأ) وهامش شاذ بنافذة القوانين.
- **معالجة الأخطاء**: أهم إصلاح — انقطاع الاتصال بالسيرفر بشكل غير متوقع (واي فاي، تعطّل المضيف) كان يجمّد الشاشة بصمت بدون أي رسالة؛ الآن يظهر تنبيه واضح مع زر رجوع. أضفت أيضًا `ErrorBoundary` على مستوى التطبيق كامل (بديل عربي قابل لإعادة المحاولة بدل شاشة بيضاء/حمراء عند أي خلل تنفيذ) وشاشة "الصفحة غير موجودة".
- **الأيقونة النهائية**: تصميم بسيط من هوية التطبيق (بطاقة كريمية بحد ذهبي على أخضر داكن، مع رمز ورق) — SVG مبني برمجيًا (`scripts/generate-icon.mjs`) ومُصدَّر لكل الأحجام الستة التي يحتاجها `app.json` (iOS/الويب، وطبقات أيقونة أندرويد التكيفية الثلاث). لا يعتمد على أي عمل تصميم خارجي.

**تبعيات جديدة**: `expo-audio` + `expo-asset` (تشغيل الصوت) — تبعية native جديدة تحتاج إعادة بناء Dev Client، بنفس فئة الكاميرا/TCP بيوم 2. `sharp` كـ devDependency فقط (توليد الأيقونة وقت التطوير، ما يدخل حزمة التطبيق نفسها).

**تم التحقق فعليًا (وليس فقط بالكود)**: `tsc --noEmit` نظيف، `expo-doctor` (21/21 — صلّحت بالمناسبة انحراف نسخ كان موجود من قبل بعدة حزم Expo)، `validate:content` نظيف. تحقق حي بالمتصفح: أنشأت حساب اختباري ولعبت جولة كاملة (اختيار فئة ← رهان ← كشف السؤال ← منح نقاط ← دوران الدور) بدون أي خطأ بالـ console، تأكدت من ترتيب شبكة المواضيع RTL بقياس الإحداثيات الفعلية، وفعّلت `ErrorBoundary` عمدًا (بحقن خطأ مؤقت أزلته فورًا بعدها) وشفت الواجهة العربية البديلة تظهر بالضبط كما هو متوقع، وجربت شاشة "الصفحة غير موجودة" والرجوع منها.

**غير مُتحقق منه**: جودة الصوت الفعلية على جهاز حقيقي (ما أقدر أسمع بالمتصفح، بس تأكدت إن كل استدعاء صوت يشتغل بدون خطأ)، سلوك التمرير الأفقي بلوحة النقاط لما يكون فيه أكثر من ~7 لاعبين متزامنين (يحتاج جلسة سيرفر فعلية بعدة أجهزة ما قدرت أحاكيها لوحدي)، وشكل الأيقونة النهائي بمشغّل تطبيقات حقيقي (أندرويد/iOS).

**بناء APK للاختبار**: `eas.json`'s `preview` profile جاهز أصلاً (`distribution: internal`, `android.buildType: apk`) — ما احتاج أي تعديل. ما شغّلت `eas build` بنفسي لأنه يعتمد على حسابك بـExpo، وتثبيته واختباره على جهاز حقيقي خطوة لازم تسويها أنت:

```bash
npx eas build --profile preview --platform android
```

بعد ما يخلص، نزّل الـ APK وثبّته على جهازك (نفس أسلوب قسم Dev Client بالأعلى) — لازم إعادة بناء لأن `expo-audio`/`expo-asset` تبعيات native جديدة.
